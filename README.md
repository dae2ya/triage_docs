# salesforce_triage-docs

로컬 문서(PDF · Word · PPT · Excel)를 **Salesforce Data 360에 업로드하기 전에** 사전 트리아지(triage)하는 CLI 도구입니다.
각 파일에 어떤 파서(**Docling** / **LLM Parser** / **검토**)가 알맞은지 판정하고, 중복·손상·대용량을 가려내 **단일 CSV 한 장**으로 정리합니다. 선택적으로 판정 결과대로 파일을 폴더 분류(이동)까지 해 줍니다.

파싱 비용과 품질은 파서 선택에 크게 좌우됩니다. 이 도구는 업로드 전에 "무엇을 어떤 파서로 넣을지"를 미리 걸러, 잘못된 파서로 인한 파싱 실패·비용 낭비를 줄이는 것이 목적입니다.

---

## 왜 필요한가

| 파일 성격 | 권장 파서 | 이유 / 부작용 |
|---|---|---|
| 텍스트·표가 많은 문서 (보고서 Word, 표·수치 Excel, 텍스트 PDF) | **Docling** | 문단·표·셀 구조를 살려 읽기에 강함 |
| 이미지가 많은 문서 (사진·캡처 슬라이드, 이미지형 PDF) | **LLM Parser** | Docling은 이미지를 텍스트로 못 풀어 내용 누락 |
| 차트가 이미지가 아니라 **벡터/텍스트**로 그려진 문서 | **LLM Parser** | ⚠️ Docling은 벡터 차트를 선·좌표 조각으로 파편화해 표/수치가 깨짐 |
| 내용 거의 없음 / 스캔본 | **검토** | 사람 확인·OCR 필요 |
| 구형 바이너리 (.doc/.ppt/.xls) | **검토** | 구조 분석 불가 — `.docx/.pptx/.xlsx`로 변환 후 재판정 |

## 사전점검 항목

Data 360 업로드 전 점검 체크리스트를 도구가 다음과 같이 커버합니다.

| # | 점검 항목 | 이 도구의 대응 |
|---|---|---|
| 1 | 파일 유형별 개수·용량 분포 | 콘솔 **유형별 분포** 요약(확장자별 개수·총용량) |
| 2 | 대용량 파일 식별 | **2단계**: 75MB↑ = 대용량 경고, **2GB↑ = 업로드 불가**(Market Insight Uploader 2GB/file 제한). `용량_상태` 컬럼 |
| 3 | 중복 파일 식별 | **SHA-256 내용 해시** 기반 중복 판정 (`중복여부`/`원본파일`) |
| 4 | 손상·**암호화** 파일 검사 | 열기 실패=손상, 비밀번호/OLE 컨테이너=**암호화**로 구분 (`정상여부`) |
| 5 | 파일명 유효성 검사 | 이름 120자↑ / 특수문자 / 경로 255자↑ 위반 표기 (`이름검사` 컬럼) |
| 6 | PDF 변환 대상 식별 | 구형 포맷 등 변환 권장 대상 표기 (`변환대상` 컬럼) |

> 파일명 검사·용량 판정·변환대상은 **표시만** 하며 실제 파일은 변경하지 않습니다. 판단은 사람이 합니다.

## 요구 사항

- Python 3.8+
- [`pypdf`](https://pypi.org/project/pypdf/) — PDF 판정에 필요 (없으면 PDF는 "미설치" 표기, 나머지 형식은 정상 동작)

```bash
pip install pypdf
```

Office 형식(docx/pptx/xlsx)은 표준 라이브러리(zipfile·re)만으로 분석하므로 별도 의존성이 없습니다.

## 사용법

```bash
# 폴더 하나를 훑어 결과 CSV만 생성 (파일은 안 옮김)
python3 triage_docs.py ~/Downloads

# 하위 폴더까지 재귀 탐색
python3 triage_docs.py ~/Downloads --recursive

# 판정 결과대로 파일을 폴더로 이동
python3 triage_docs.py ~/Downloads --recursive --move

# 이동 목적지 직접 지정
python3 triage_docs.py ~/Downloads --recursive --move --dest ~/Downloads/분류결과

# 파일·폴더 여러 개 + CSV 이름 지정
python3 triage_docs.py a.pdf ~/docs b.pptx --csv ~/Downloads/out.csv

# 엑셀(요약 + 상세 2시트)로 저장 — 콘솔 요약이 '요약' 시트에 그대로 담김
python3 triage_docs.py ~/Downloads --xlsx
python3 triage_docs.py ~/Downloads --csv ~/Downloads/out.xlsx   # .xlsx 경로면 자동으로 엑셀
```

**권장 순서:** 먼저 `--move` 없이 돌려 `Triage 결과.csv`로 결과를 확인하고, 분류가 맞으면 `--move`를 붙여 실제로 정리하세요.

### 옵션

| 옵션 | 설명 |
|---|---|
| `paths` | 파일 또는 폴더 (여러 개 가능) |
| `--csv <경로>` | 결과 파일의 저장 위치/이름. 폴더면 그 안에 `Triage 결과.csv`(또는 `--xlsx`면 `.xlsx`) 생성. 경로가 `.xlsx`로 끝나면 자동으로 엑셀. 생략 시 `--move` 목적지 밑에, 이동이 없으면 스캔 폴더에 저장 (CSV는 Excel용 UTF-8 BOM) |
| `--xlsx` | CSV 대신 엑셀(`.xlsx`)로 저장. **`요약` 시트**(유형별 분포·파서별 집계·업로드불가/대용량/손상 목록 = 콘솔 요약 그대로) + **`상세` 시트**(파일별 판정 표) 2장. 외부 라이브러리 없이 표준 라이브러리로 생성 |
| `--move` | 판정 결과대로 파일을 하위 폴더로 이동 |
| `--dest <경로>` | `--move` 시 이동 목적지 루트 (기본: `~/Downloads/_triage`) |
| `--recursive` | 하위 폴더까지 재귀 탐색 |
| `--large-mb <MB>` | 대용량 경고 임계값(MB). 기본 75. 초과 시 축소 권장·`_large` 분리. **2GB 업로드불가 기준은 고정** |
| `--jobs <n>` | 병렬 프로세스 수 (기본: 코어−1). 제한 환경이면 자동 순차 폴백 |

## 판정 기준 (프로그램 실제 설정)

### PDF — 앞뒤 표본 페이지(최대 40장)만 검사해 빠르게 판정

| 조건 | → 파서 |
|---|---|
| 벡터 드로잉 과밀 — 표본의 **30%↑** 페이지가 벡터 연산 300 초과 | LLM Parser |
| 벡터 **15%↑** 또는 텍스트 과밀(문자 900 초과 페이지가 **40%↑**) | LLM Parser |
| 텍스트·이미지 거의 없음 (페이지당 문자 50 미만 & 이미지 0.3 미만) | 검토 |
| 그 외 (이미지·텍스트 기반, 과밀 낮음) | Docling |

### Office (docx / pptx / xlsx) — ZIP 내부 text/media/chart 카운트

| 조건 | → 파서 |
|---|---|
| Word/PPT: 본문 텍스트 200자 미만 + 이미지/차트 존재 | LLM Parser |
| Word/PPT: 텍스트 200자 이상 | Docling |
| Excel: 표·수치·차트가 있으면 (빈 통합문서가 아니면) | Docling |
| 내용 거의 없음 (빈 파일 의심) | 검토 |

경계에 걸치는 파일은 CSV의 **이유** 컬럼에 실제 측정 수치가 함께 적히니, 애매하면 그 수치를 보고 최종 결정하세요.

## 출력 필드

기본 출력은 아래 컬럼을 가진 **상세 표 한 장(CSV)** 입니다. `--xlsx`(또는 `.xlsx` 경로)를 주면
같은 상세 표가 `상세` 시트에 들어가고, 그 앞에 `요약` 시트가 한 장 더 붙습니다 — 유형별 분포,
파서별 집계, 업로드불가·대용량·손상·파일명 위반 목록(= 콘솔에 찍히던 요약)이 그대로 표로 담깁니다.

### 상세 시트 / CSV 컬럼

| 컬럼 | 내용 |
|---|---|
| 번호 | 정렬 후 매긴 순번 |
| 파일명 / 경로 | 파일 이름과 전체 경로(`--move` 후에는 옮겨진 경로). 한글은 Excel에서 깨지지 않도록 NFC로 정규화 |
| 형식 | pdf · docx · pptx · xlsx · doc … |
| 권장_파싱방식 | LLM Parser · Docling · 검토 |
| 이유 | 판정 근거(단서 수치 포함) |
| 용량 | 1GB 이상은 GB, 그 외 MB (예: `73.9MB`, `2.31GB`) |
| 용량_상태 | `업로드불가`(2GB↑) / `대용량`(경고선↑) / 빈칸 |
| 용량_추천 | 2GB↑면 "업로드 불가·분할/변환 필수", 경고선↑면 축소 방법 안내, 이하면 빈칸 (안내 문구일 뿐 자동 압축은 하지 않음) |
| 변환대상 | 직접 텍스트 추출이 까다로워 변환을 권하는 대상(구형 포맷 등), 아니면 빈칸 |
| 이름검사 | 파일명 유효성 위반 사유(이름 120자↑ / 특수문자 / 경로 255자↑), 없으면 빈칸 |
| 중복여부 / 원본파일 | 원본·중복·고유 / 같은 내용인 원본 파일명 |
| 정상여부 | 정상 / 손상(원인) / **암호화**(원인) |

정렬 순서: 손상 → LLM Parser → 검토 → Docling, 그 안에서는 이름순.

## `--move` 폴더 분류

우선순위대로 **먼저 걸리는 폴더**에 들어갑니다.

| 우선순위 | 이런 파일이 | 이 폴더로 |
|---|---|---|
| 1 | 손상·암호화·미지원 | `_errors` |
| 2 | 중복 | `_duplicates` |
| 3 | 업로드불가(2GB↑) | `_oversize` |
| 4 | 대용량(75 MB↑) | `_large` |
| 5 | 그 외 원본·고유 | `LLM_Parser` · `Docling` · `검토` |

- 중복은 **SHA-256 내용 해시**로 판정합니다(파일명이 아니라 내용 기준).
- **2GB 초과**는 Uploader가 업로드 자체를 거부하므로 최우선으로 `_oversize`로 분리합니다 — 분할·변환이 필수입니다.
- 대용량(75MB↑)은 파서 폴더보다 먼저 `_large`로 빠집니다 — 파싱 전에 용량부터 줄이라는 뜻입니다. **파일을 자동으로 압축하지는 않습니다**(재인코딩이 오히려 용량을 키우는 경우가 있어 분리만 하고, 축소는 사람이 판단).
- 같은 이름이 있으면 `(2)`, `(3)`…을 붙여 덮어쓰지 않습니다.

## 참고

- **NFC 정규화** — macOS는 파일명을 NFD(분해형)로 저장(`년` = `ㄴ`+`ㅕ`+`ㄴ`)하기 때문에 Excel·Windows에서 한글이 자모 분리로 깨져 보입니다. CSV에 쓰는 파일명·경로·원본파일만 NFC로 정규화하며, **실제 파일 이름은 건드리지 않습니다.**
- **파일명 검사 기준** — 이름 길이 120자 이상 / 금지 특수문자(`\ / : * ? " < > |` 및 제어문자) 포함 / 전체 경로 255자 이상이면 `이름검사` 컬럼에 표기합니다. NFD 자모분리 자체는 위반으로 보지 않습니다(NFC 정규화로 표시만 정상화). **표시만 하고 실제 파일은 변경하지 않습니다.**
- 자세한 설명은 [`triage_docs_manual.html`](triage_docs_manual.html) 참고 (부록에 파일 타입별 파서 권장 표 포함).
