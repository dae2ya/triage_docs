triage_docs.py

Data 360에 올리기 전, 로컬 문서(PDF·Word·PPT·Excel)를 한꺼번에 훑어 파일마다 어떤 파서가 맞는지, 그리고 용량이 큰 파일은 어떻게 줄일지를 CSV 한 장으로 정리해 주는 도구입니다.

파일을 실제로 파싱하려면 시간과 비용이 큽니다. 특히 LLM Parser가 그렇죠. 그래서 이 도구는 파싱 없이 얻을 수 있는 가벼운 단서만으로 먼저 분류해, 비싼 LLM Parser는 정말 필요한 파일에만 쓰도록 걸러 줍니다. 또 용량이 큰 파일은 따로 골라내 비용을 줄일 방법까지 함께 짚어 줍니다. pypdf 외에는 별도 설치가 필요 없습니다.

1. 설치 & 실행

# PDF를 볼 때만 필요합니다 (Office는 별도 설치 없이 동작)
pip install pypdf

# 폴더 하나를 훑어 CSV로 저장 (스캔 폴더에 'Triage 결과.csv' 생성)
python3 triage_docs.py ~/Downloads

# 하위 폴더까지 훑고, 판정 결과대로 파일을 폴더별로 이동
python3 triage_docs.py ~/Downloads --recursive --move

# 파일·폴더를 여러 개 섞어 지정해도 됩니다
python3 triage_docs.py fileA.pdf ~/docs deckB.pptx --csv out.csv

옵션

옵션설명
--csv <경로>결과 파일의 저장 위치입니다(CSV는 Excel에서 한글이 깨지지 않는 UTF-8 BOM). 경로가 .xlsx로 끝나면 자동으로 엑셀로 저장합니다. 생략하면 --move 목적지(_triage) 바로 밑에, 이동이 없으면 스캔한 폴더에 Triage 결과.csv(또는 --xlsx면 .xlsx)로 저장합니다.
--xlsxCSV 대신 엑셀(.xlsx)로 저장합니다. 요약 시트(유형별 분포·파서별 집계·업로드불가/대용량/손상/파일명 위반 목록 = 콘솔에 찍히는 요약 그대로)와 상세 시트(파일별 판정 표) 두 장이 만들어집니다. 외부 라이브러리 없이 표준 라이브러리만으로 생성하므로 별도 설치가 필요 없습니다.
--move판정 결과대로 파일을 하위 폴더로 이동합니다(4·6절 참고). 지정하지 않으면 파일은 그대로 두고 결과 파일만 만듭니다.
--dest <폴더>--move로 옮길 목적지 폴더입니다(기본값 ~/Downloads/_triage).
--large-mb <MB>대용량 경고선(MB)입니다. 기본값 75. 넘으면 _large로 분리하고 축소를 권합니다. 2 GB 업로드불가 기준은 고정이라 이 값과 무관합니다.
--jobs <N>동시에 돌릴 프로세스 수입니다(기본값은 CPU 코어 −1). 병렬이 막힌 환경이면 자동으로 하나씩 처리합니다.
--recursive하위 폴더까지 훑습니다. 지정하지 않으면 폴더 바로 아래 파일만 봅니다.

※ 결과 CSV 파일명은 Triage 결과.csv입니다(따로 --csv out.csv처럼 이름을 주면 그 이름으로). --move로 옮길 때는 결과 CSV도 _triage 폴더 바로 밑에, 분류된 파서 폴더들과 나란히 놓입니다.

2. 지원 형식

형식분석 방식
.pdfpypdf로 벡터·이미지·텍스트 단서를 읽어 판정합니다.
.docx .pptx .xlsx속을 열면 ZIP+XML 구조입니다. 별도 설치 없이 내부의 차트 XML·이미지·텍스트를 직접 세어 판정합니다.
.doc .ppt .xls옛 바이너리 형식이라 속을 들여다볼 수 없어 검토로 분류합니다(신형으로 변환 후 다시 돌리길 권합니다).

※ Office가 문서를 열어 둘 때 만드는 ~$ 임시 잠금 파일은 알아서 건너뜁니다.

3. 권장 파싱방식 판정 기준

PDF — 파싱 없이 읽는 단서 3가지

모두 파일을 열어 개수·길이·비율만 세는 값이라 빠르고 가볍습니다. 페이지가 많으면 앞뒤 40장만 표본으로 봅니다.

  • vec_ratio — 벡터 선·도형을 그리는 명령이 빽빽한 페이지의 비율입니다. ← 이 값이 벡터 차트를 가려내는 결정적 단서입니다. 로고 이미지는 명령 하나, 벡터 차트는 명령 수백 개라 확연히 갈립니다.
  • dense_ratio — 글자가 빽빽한 페이지의 비율입니다.
  • img_per_page — 페이지당 이미지 수입니다. (로고·장식에 쉽게 부풀려지므로 이 값 하나만으로는 판단하지 않습니다.)
이런 파일이면판정왜냐하면
벡터 그래픽이나 글자가 빽빽함LLM Parser벡터 차트는 Docling이 글자 조각으로 잘게 쪼개 버립니다. LLM이 그림 전체를 보고 의미를 되살립니다.
이미지·텍스트 위주에 빽빽하진 않음Docling구조대로 읽어도 충분합니다.
글자도 이미지도 거의 없음검토스캔본이거나 빈 파일일 수 있어 OCR 여부를 사람이 확인해야 합니다.

Office — 속을 세어 사실대로 판정

Office 파일은 차트가 charts/chart*.xml에 데이터로 또렷이 들어 있어, PDF처럼 차트가 조각나는 문제가 없습니다. 그래서 차트 XML·이미지(media/)·텍스트 개수를 직접 세어 판정합니다.

이런 파일이면 (docx·pptx)판정왜냐하면
읽을 만한 텍스트가 있음Docling구조대로 읽어도 충분합니다.
텍스트는 거의 없고 이미지 위주LLM Parser화면을 캡처해 붙인 슬라이드형이라, 이미지에서 의미를 다시 읽어내야 합니다.
텍스트·차트·이미지가 모두 없음검토빈 파일일 수 있습니다.

※ XLSX는 표와 숫자가 본질이라 항상 Docling으로 봅니다(표는 구조대로 읽는 게 정답). 빈 시트만 검토입니다.

4. 용량 판정

용량은 두 단계로 봅니다. 하나는 업로드 자체가 막히는 하드 한계(2 GB), 다른 하나는 파싱·임베딩 부담을 알리는 경고선(기본 75 MB)입니다. 어느 쪽이든 파일을 자동으로 압축하지는 않습니다 — 줄일지·어떻게 줄일지는 사람이 판단합니다.

  • 2 GB 초과 = 업로드 불가 — Market Insight Uploader가 파일당 2 GB를 넘으면 업로드 자체를 거부합니다. 이런 파일은 최우선으로 _oversize로 분리하며, 분할하거나 변환해야 올릴 수 있습니다.
  • 경고선(기본 75 MB) 초과 = 대용량 — 올릴 수는 있지만 파싱·임베딩에 시간과 메모리가 큽니다. _large로 분리해 눈에 띄게 하고, 줄인 뒤 파싱하도록 안내합니다. 경고선은 --large-mb <MB>로 조절합니다(2 GB 하드 한계는 고정).
  • 용량이 왜 커지나 — 거의 항상 내부에 박힌 이미지(고해상도 사진·스크린샷) 때문입니다. 텍스트·차트 XML은 아무리 많아도 수 MB를 넘기 어렵습니다.
  • 어떻게 줄이나 — 필요하면 PowerPoint·Word의 그림 압축 기능이나 이미지 해상도 낮추기, 불필요한 이미지·슬라이드 제거로 용량을 낮춘 뒤 파싱하세요. 줄이더라도 텍스트·차트·표는 건드리지 않아야 파서 판정과 파싱 결과가 유지됩니다.
이런 파일이면프로그램 동작왜냐하면
2 GB↑용량_상태=업로드불가 · _oversize 폴더로 분리 + CSV 용량_추천에 분할/변환 안내Uploader가 2 GB/파일을 넘으면 받지 않습니다. 나눠 올리거나 형식을 바꿔야 합니다.
75 MB↑ (경고선)용량_상태=대용량 · _large 폴더로 분리 + CSV 용량_추천에 축소 안내원본을 그대로 두고 따로 모아, 사람이 용량을 줄인 뒤 알맞은 파서 폴더로 옮기도록 합니다.
경고선 이하—그대로 올려도 부담이 적습니다.
왜 자동 압축을 안 하나? 자동 이미지 재압축은 파일에 따라 오히려 용량이 더 커지는 경우가 있어(재인코딩 오버헤드·이미 최적화된 이미지 등), 이 도구는 대용량만 분리해 알려 주고 실제 축소는 사람이 확인하며 처리하도록 합니다.

5. 파일 이동 (--move)

--move를 주면 판정 결과대로 파일을 목적지 폴더(--dest, 기본 ~/Downloads/_triage) 아래로 옮깁니다. 아래 순서로 먼저 걸리는 곳에 들어갑니다.

우선순위이런 파일이이 폴더로
1손상·암호화·미지원_errors
2중복_duplicates
3업로드불가(2 GB↑)_oversize
4대용량(75 MB↑)_large
5그 외 원본·고유LLM_Parser · Docling · 검토

※ 2 GB 초과는 Uploader가 업로드 자체를 거부하므로 최우선으로 _oversize로 분리합니다 — 분할·변환이 필수입니다. 대용량(75 MB↑)은 파서 폴더보다 먼저 _large로 빠집니다 — 파싱에 넣기 전에 용량부터 줄이라는 뜻입니다. 원본을 그대로 모아 두므로, 용량을 줄인 뒤 알맞은 파서 폴더로 옮겨 파싱하세요. 파일을 자동으로 압축하지는 않습니다. 목적지에 같은 이름이 있으면 (2), (3)…을 붙여 덮어쓰지 않습니다.

6. 중복 · 정상 · 암호화 · 파일명 검사

  • 중복여부 — 파일 내용이 완전히 같은지를 SHA-256 값으로 확인합니다(파일명이 아니라 내용 기준). 같은 내용끼리 묶어 이름순 첫 파일은 원본, 나머지는 중복, 짝이 없으면 고유로 표시하고, 중복인 파일에는 어떤 원본파일과 같은지를 함께 적어 줍니다.
  • 정상여부 (정상 / 손상 / 암호화) — 파일이 열리고 내용이 있으면 정상, 열리지 않거나 비어 있으면 손상과 원인을 적습니다. 비밀번호가 걸린 파일은 암호화로 따로 구분해 검토로 분류합니다 — PDF는 pypdf가 암호화 플래그를 알려 주고, Office(docx·pptx·xlsx)는 암호화되면 ZIP이 아니라 OLE 컨테이너(D0 CF 11 E0)로 감싸지므로 그 서명으로 가려냅니다. 해제한 뒤 다시 올려야 파싱됩니다.
  • 이름검사 — 파일명이 아래를 어기면 이름검사 컬럼에 사유를 적습니다(여러 개면 ;로 이어붙임). 표시만 하며 실제 파일 이름은 바꾸지 않습니다.
    • 이름 길이 120자 이상
    • 금지 특수문자 포함 — \ / : * ? " < > | 및 제어문자
    • 전체 경로 길이 255자 이상
    ※ macOS의 NFD 자모분리 자체는 위반으로 보지 않습니다(NFC 정규화로 표시만 정상화).

7. 출력 필드

기본 출력은 아래 컬럼을 가진 상세 표 한 장(CSV)입니다. --xlsx(또는 .xlsx 경로)를 주면 같은 상세 표가 상세 시트에 들어가고, 그 앞에 요약 시트가 한 장 더 붙습니다 — 유형별 분포, 파서별 집계, 업로드불가·대용량·손상·파일명 위반 목록(화면 아래에 찍히는 요약)이 그대로 표로 담깁니다.

손댈 파일이 먼저 눈에 띄도록 정렬합니다: 손상 → LLM Parser → 검토 → Docling, 그 안에서는 이름순입니다. 실행하면 화면 맨 아래에 파서별 요약(LLM Parser=n Docling=n 검토=n 손상=n | 중복=n), 유형별 분포(확장자별 개수·총용량), 파일명 검사·변환 대상 건수, 그리고 업로드 불가(2 GB↑)·대용량(경고선↑) 목록이 뜹니다.

※ macOS는 파일명을 NFD(분해형)로 저장하기 때문에(년 = ㄴ+ㅕ+ㄴ), 그대로 Excel·Windows에서 열면 한글이 자모 분리로 깨져 보입니다. 그래서 CSV에 쓰는 파일명·경로·원본파일만 NFC(조합형)로 정규화합니다 — 실제 파일 이름은 건드리지 않으며, 표시만 깔끔해집니다.

부록 A. 파일 타입별 파서 권장 요약

한눈에 보는 파일 타입 → 권장 파서 매핑입니다. 아래 규칙이 프로그램의 실제 판정과 같습니다.

파일 성격대표 예시권장 파서이유 / 부작용
텍스트·표가 많은 문서 보고서 Word(docx), 표·수치 위주 Excel(xlsx), 텍스트 위주 PDF Docling 문단·표·셀 구조를 그대로 살려 읽는 데 강합니다. 구조화 문서는 Docling이 가장 정확하고 저렴합니다.
이미지가 많은 문서 사진·스크린샷·캡처가 대부분인 슬라이드(pptx), 텍스트가 거의 없는 이미지형 docx, 이미지 위주 PDF LLM Parser 이미지 안의 의미를 재구성해야 합니다. Docling은 이미지를 텍스트로 풀지 못해 내용이 통째로 누락됩니다.
차트가 이미지가 아니라 벡터/텍스트로 그려진 문서 PDF 안에 선·도형으로 그린 차트, 벡터 다이어그램 과밀 PDF LLM Parser Docling 부작용: 벡터 차트를 선·좌표 조각으로 파편화해 표/수치가 깨집니다. LLM Parser가 차트의 의미를 재구성합니다.
내용이 거의 없음 / 스캔본 빈 파일, 텍스트·이미지 모두 희박한 PDF, 스캔만 된 이미지 PDF 검토 파서를 정하기 전에 사람이 확인해야 합니다. 스캔본은 OCR이 먼저 필요할 수 있습니다.
구형 바이너리 포맷 .doc · .ppt · .xls 검토 구조 분석이 불가합니다. .docx/.pptx/.xlsx로 변환한 뒤 다시 판정하세요.
